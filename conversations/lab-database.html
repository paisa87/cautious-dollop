Building a Lab Management Database with Claude Code

Claude Lab & Research Spring 2026
Context: I needed a lab management system for the VGCC Biotech lab — something like Quartzy or FileMaker, but free, customized to our SOPs, and runnable locally by three non-technical users. I opened a Claude Code session and asked it to play the role of a software engineer gathering specifications. What followed was an iterative build across multiple sessions: requirements gathering, file upload troubleshooting, schema design, full-stack code generation, data import from an existing inventory spreadsheet, and live bug fixing when the app threw an error on first login.

Phase 5 — Bug fix on first login
You
[Screenshot attached] I got the following error after following the setup and install instructions for Windows. This is the error screen after I try logging in with the default user and password.
Claude
⚠ Jinja2 template bug — diagnosed and fixed from screenshot I can see the error — “block ‘content’ defined twice” is a Jinja2 error. In base.html, the {% block content %} tag appeared inside both branches of an {% if %} statement, which Jinja2 forbids. The fix was to move the content block outside the if/else entirely so it appears exactly once, unconditionally.

What the bug was: Jinja2 has a rule that a named block like {% block content %} can only appear once per template. Our base.html had it in both the “logged in” and “logged out” branches of an if statement — which crashed on every page load.

Fixed and pushed. To apply the fix:
  • If you downloaded the ZIP — download it again from GitHub and replace the old files.
  • If you used git clone — run git pull origin claude/lab-management-database-LiuEg in your Command Prompt, then rerun run.bat.

What I took away

  • Asking Claude to play the role of a software engineer gathering requirements produced a structured, professional intake process I wouldn’t have designed myself. The questions it asked (roles vs. access levels, run frequency, storage granularity) shaped the entire architecture before a line of code was written.
  • Claude read all 22 lab files — SOPs, data sheets, the inventory spreadsheet — and built a system that matched the actual workflows (VG001–VG009 SOPs mapped directly to modules). Document-grounded code generation is qualitatively different from asking an AI to “build a lab database.”
  • The inventory importer auto-loaded 223 items from the existing .xlsx. That migration step alone would have taken hours to do manually.
  • Rate limits and session timeouts are a real constraint for long build sessions. Claude hit usage limits mid-build multiple times. Knowing to just continue in a new session (rather than starting over) kept progress intact.
  • The first login crash was diagnosed and fixed from a screenshot alone. Being able to show an AI an error screen and get a root-cause explanation + patch is a genuinely different kind of debugging support than a Stack Overflow search.
  • The file upload coaching moment (forgetting to click “Commit changes” on GitHub) is a good reminder that AI tools work within the boundaries of your technical setup — getting files into the right place is still on you.
